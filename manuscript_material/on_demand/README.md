# On-demand figures (BixBench-Verified-50)

These figures were made on request. They are not among the submitted display items and are not cited in the Results. They are generated by `scripts/fig_on_demand.py` from the archived inputs that `build_data.py` reads (`BixBench50_CompBio_analysis/analysis.json`, the failure ledger `analysis_reports/galaxy_improvement_20260924/v2_trace_friction/ledger.json` and `source_data/derived/run_summaries.jsonl.gz`). Running the script does not change `figure_data.json`.

```bash
python manuscript_material/scripts/fig_on_demand.py   # from the repository root, Python 3.12 + scripts/requirements.txt
```

All three figures use BixBench-Verified-50, the benchmark with a binary score for every run and a primary cause for every scored-incorrect run. CompBioBench has no per-run grades in the archive, and the IWC endpoint is continuous. A replicate set is the three replicate runs of one task × model configuration × execution condition. All five model configurations are shown, including the superseded Claude Code agent harness. Where they are pooled, the pooling matches Fig. 4b: 250 replicate sets per condition.

Each figure has a vector PDF (editable TrueType text), a 300-dpi PNG preview and a Source Data workbook.

## Legends

**On-demand Fig. 1 | Primary cause of scored-incorrect runs, by how many of the three replicate runs were scored incorrect.** (`OD_Fig1_error_types_by_incorrect_replicates`)
Replicate sets with **a**, one; **b**, two; or **c**, all three replicate runs scored incorrect. Bars give the share of scored-incorrect runs in that group with each primary cause, from the run-level failure ledger (Supplementary Table 14e). The number of runs is at the bar end; open-ended code is the upper bar in each pair. The header of each panel gives the runs and replicate sets per condition.

- **a**: 21 runs in 21 replicate sets (open-ended code) and 20 in 20 (Galaxy). A single scored-incorrect replicate run was mostly a statistical or reasoning error (13 of 21; 15 of 20).
- **b**: 24 runs in 12 sets and 16 in 8. Causes were mixed.
- **c**: 90 runs in 30 sets and 75 in 25. When all three runs were scored incorrect, the task was under-specified or the reference ambiguous, or the evaluator rejected a correct answer, in 70 of 90 open-ended code runs and 70 of 75 Galaxy runs.

The split sets (a + b: 33 and 28) and the sets with all three runs incorrect (c: 30 and 25) match Fig. 4b.

**On-demand Fig. 2 | Unanimous accuracy per model configuration.** (`OD_Fig2_unanimous_accuracy`)
Unanimous accuracy is the share of the 50 tasks whose three replicate runs were all scored correct. It is shown for the open-ended code condition and then the Galaxy condition. The right column gives the condition difference (Galaxy − open-ended code) in percentage points, with a 95% percentile cluster-bootstrap interval that resamples source capsules (20,000 resamples, seed 20260929), as elsewhere in the manuscript.

The Galaxy condition was higher for every model configuration: +2.0, +4.0, +4.0, +2.0 and +8.0 points. Every interval includes zero; the interval for GPT-5.5 is 0.0 to +6.8. Pooled differences are +3.0 (−4.2 to +10.7) for the four Codex model configurations and +4.0 (−2.8 to +11.3) for all five. Run-level accuracy is compared with unanimous accuracy in Fig. 4e.

**On-demand Fig. 3 | Input-token usage of scored-correct and scored-incorrect runs.** (`OD_Fig3_input_tokens_correct_vs_incorrect`)
Input-token usage per run, in millions on a log scale, per model configuration. Panel **a** shows the open-ended code condition and panel **b** the Galaxy condition. Light boxes are scored-correct runs and solid boxes scored-incorrect runs. Each dot is one run, and the numbers along the bottom give the runs per box. Boxes span the middle 50% of runs and mark the median. Whiskers extend to 1.5 times the interquartile range. Input-token usage includes cached input, as in Fig. 3c; output tokens, 0.6% of input, are not added. Scored-incorrect runs include runs that submitted no answer.

*Statistics.*
- **Between runs (above each pair).** The number above each pair is the median ratio, scored incorrect ÷ scored correct, with a two-sided Mann–Whitney U test. P values are Holm-adjusted over the ten comparisons. A bracket and bold text mark P < 0.05. The three replicate runs of a task are not independent, so these P values may be optimistic. Each ratio also has a 95% percentile cluster-bootstrap interval, resampling source capsules (20,000 resamples, seed 20260929), in the `ab_tests_incorrect_vs_correct` sheet.
- **Within task (panel headers).** In each split replicate set, the scored-incorrect run(s) are compared with the median of their scored-correct siblings, using the mean log₂ ratio per set. A two-sided Wilcoxon signed-rank test is then run over the sets (`ab_within_task_test`, `ab_within_task_sets`).

*Results.*
- **a, open-ended code.** Scored-incorrect runs had higher median usage in all five model configurations (ratio 1.28 to 1.96).
  - Only DeepSeek V4 Pro (Codex) reached significance after adjustment: 1.95×, adjusted P = 0.037.
  - Its cluster-bootstrap interval, 0.99 to 6.41, includes 1, so the difference does not survive the dependence between runs of one task.
  - The superseded Claude Code agent harness had P = 0.010 unadjusted and 0.094 adjusted. The other adjusted P values were 0.23 to 1.00.
- **b, Galaxy.** No difference was significant (ratio 0.96 to 1.02; every adjusted P = 1.00).
- **Within task.** For the same task and model configuration, scored-incorrect runs used as many input tokens as their scored-correct siblings:
  - open-ended code: 0.99×, P = 0.74, 33 sets;
  - Galaxy: 1.01×, P = 0.96, 28 sets.

  The higher medians in **a** therefore reflect which tasks the runs failed on, not extra tokens spent on a wrong answer.
