# Responses to the manuscript-layout comments

Revised 2 October 2026. All numbers come from retained archive records and are regenerated by `build_all.sh`; no new benchmark run, expert adjudication or deployment was performed. "Galaxy" and "code" mean the assigned arms as deployed: their prompts, budgets, campaigns and runtime environments differ (Results 1, Methods).

## Structure

Results follow the requested order: (1) a paired benchmark of biomedical agents in Galaxy and open-ended code (the experimental setup); (2) Galaxy matches open-ended code; (3) failures reflect insufficient verification more than missing knowledge; (4) Galaxy's token overhead is concentrated in addressable interface costs. UDT usage is discussed in section 2, as requested. Section 4 ends with the explicitly marked token-reduction placeholder (Fig. 6f).

## Section 2 — Galaxy matches open-ended code

**a. Overall accuracy is similar.** BixBench acceptance 85.2% (code) versus 86.5% (Galaxy), difference +1.3 points (−3.5 to 6.4); CompBioBench agreement 86.7% versus 87.1%, +0.4 (−1.6 to 2.4). Both stay within about one point of zero under the benchmark-side and outcome-named-campaign sensitivities. IWC agreement 0.940 versus 0.980; three tasks with a zero-scored run explain most of that difference. Similar, not formally equivalent: no equivalence margin was prespecified.

**b. What is the evidence that accuracy varies by benchmark, with no one model fitting all?** The leading configuration changes: GPT-5.5 leads BixBench in both arms (87.3% and 89.3%), Sol leads CompBioBench in both (91.0% and 92.0%), Sol leads IWC code (0.988) and DeepSeek V4 Pro leads IWC Galaxy (0.999). These are rank changes, but the leaders' intervals overlap, so they are not a demonstrated model-by-benchmark interaction. The manuscript states this as "the best configuration depended on the benchmark", which the data support, and recommends evaluating on the intended workload.

**c. What is the evidence that Galaxy increases the stability of reaching the correct answer?** The share of task–configuration sets with all three attempts correct rose from 79.5% to 82.5% (BixBench) and 77.3% to 80.5% (CompBioBench), and the point estimate favoured Galaxy for all eight configuration × benchmark comparisons; every configuration's interval included or touched zero. A new cross-arm comparison shows where the gain comes from. Persistent failures (3/3 rejected) are the same in both arms: 17 BixBench task × configuration pairs failed 3/3 in both arms, out of 22 code and 20 Galaxy 3/3 sets. On CompBioBench, 15 of 25 coincided. The improvement is in sporadic failures (mixed sets 19 → 15 and 66 → 53). Discordance did not fall for every model (it rose for DeepSeek on BixBench and Sol on CompBioBench), so the manuscript claims consistency in point estimates, not a proven gain for every model.

**UDT usage.** Agents attempted UDTs in 225 of 600 BixBench and 808 of 1,200 CompBioBench Galaxy runs, from under 10% of DeepSeek BixBench runs to nearly 90% of GPT-5.5 CompBioBench runs. Runs with a completed UDT job were accepted at 92.8% (BixBench; 82.7% without UDTs) and 88.6% (CompBioBench); CompBioBench runs whose UDT jobs never completed were accepted at 81.7% (235 runs). These are associations; agents chose when to use UDTs. UDT failure modes appear in section 4.

## Section 3 — why agents fail

**The audit is a census, not a targeted sample.** It covers every BixBench task with a rejected run in any archived configuration and every CompBioBench task with a run deviating from the key, plus seven IWC workflows (93 tasks). All 73 binary-benchmark tasks with a rejected primary run are included (22 BixBench, 51 CompBioBench). The previous draft called this "targeted" and therefore declined to support the rigor claim; the build now verifies the census coverage.

**"When agents got an answer wrong, it was often gaps in rigor/validation, not biological knowledge or Galaxy knowledge."** Supported. Of 73 failing tasks, the primary cause was agent analysis in 42 (57.5%), benchmark reference, scoring or provenance in 23 (31.5%) and Galaxy platform or wrapper in 7 (9.6%). Insufficient verification was tagged in 42 failing tasks (57.5%) and in 34 of 42 agent-analysis tasks (81.0%). Domain knowledge alone explained 4 tasks (5.5%); in 17 of the 21 tasks where domain knowledge was implicated, verification was also lacking. Limits stated in the Discussion: labels are task-level and AI-assisted, tags are not knowledge tests, and blinded expert adjudication is pending.

**"Agents often are not checking their work."** Supported by the tags and by five traced cases with hashed evidence lines: a filter that dropped W and Z, read-end artifacts, in-sample fitting and scoring, circularity taken as identity, and a negative overlap check that was ignored.

**a. What is the evidence that Galaxy errors are more recoverable than shell errors?** The archive has no matched comparison of equivalent Galaxy and shell failure episodes, so the claim is not made. The nearest supported statement is in the text: 6 of the 7 tasks with a Galaxy platform cause failed only sporadically, so other attempts of the same task overcame the platform problem.

**b. What does "3 errors, 2 errors, 1 error per task" mean?** Each model configuration attempted each task three times in each arm. A set with one or two rejected attempts means the same agent sometimes succeeded and sometimes failed on that task, so the outcome depended on the analysis path it took. A set with three rejected attempts means the failure repeated every time.

**c. Do 1–2 errors reflect trajectory, and 3 errors task specification or validation rigor?** Partly. Of the 25 tasks with a persistent (3/3) set, 12 have a benchmark, reference or provenance cause and 12 agent analysis. Of the 48 tasks with only sporadic failures, 11 are benchmark-side, 30 agent analysis and 6 Galaxy platform. Persistent failures are enriched for task-specification and reference problems, and Galaxy platform problems are almost always sporadic. Insufficient verification occurs in both groups (13 of 25; 29 of 48), so it does not separate them. Shown in Fig. 4c,d.

## Section 4 — tokens

**a. Galaxy uses more tokens in all models and benchmarks.** True for BixBench and CompBioBench, not for IWC. The headline measure is now the ratio of total Galaxy to total code input tokens, which reflects aggregate cost and matches the definition behind the team's "2.8×": 4.25 (3.25–5.66) on BixBench, 2.70 (2.21–3.32) on CompBioBench and 0.90 (0.46–2.88) on IWC. GPT-5.5 on BixBench is 2.82, reproducing the 2.8× figure. On IWC, Galaxy used less total input than code for three of four configurations, because some code runs reread very long contexts (ATAC-seq code runs averaged 30.3 million input tokens against 7.9 million in Galaxy). Excluding cached context, Galaxy's point estimate exceeded code in all 12 configuration × benchmark comparisons. The earlier draft's 5.17 and 4.42 were medians of within-task ratios, now reported as a secondary measure. Claim (c), similar tokens for correct and incorrect answers, is folded into (a): within discordant sets there was no consistent difference.

**Sol is the best model relative to its token usage.** Partly. GPT-5.5 and Sol together form the accuracy–token frontier: GPT-5.5 is on it in all six benchmark–arm views, Sol in five, and Sol is the high-accuracy end (CompBioBench, IWC code). Luna is dominated in every view and DeepSeek V4 Pro in five. The manuscript says this directly; Astra is excluded because it has no Galaxy arm.

**b, c → Junhao's improvements and the concrete Galaxy issues.** Section 4 now measures the issues the agents ran into, and the measurements map to interface changes (Fig. 6):
- **Tool search does not work well.** Search plus inspection are 47–54% of calls and 44–69% of returned text; 45–53% of the tools inspected in a run were never run in it; 417 calls used a nonexistent tool ID. Search transport almost never failed, so the problem is retrieval, not availability.
- **UDTs are problematic.** 50.6% of UDT calls returned ok. On CompBioBench, 32.1% of UDT calls ended in a job error without diagnostic text, and 64.6% of failed UDT jobs failed before execution without diagnostics. Agents then resubmitted identical requests (50% of the time), 78% of which failed again, and 43.5% of CompBioBench Galaxy runs contain self-written probe UDTs.
- **Reduce the number of API calls.** Per-run Galaxy input tracks calls plus shell commands (ρ = 0.83–0.89). The largest failure classes are avoidable rounds of interaction: schema needed history context (1,119), parameter validation (769) and job errors without diagnostics (1,601).
