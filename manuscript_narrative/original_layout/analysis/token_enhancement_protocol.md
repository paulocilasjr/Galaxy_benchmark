These categories are complementary and are not additive token savings. A two-round bundled comparison can test the full package. Isolating a component requires a prespecified ablation or factorial assignment; aggregating several simultaneous changes cannot identify the effect of one.

## Matching and measurement requirements

1. Freeze the task list, input bytes, benchmark references, model/interface snapshots, containers, skills and policy versions. Keep the four primary model configurations distinct; exclude Astra from comparisons unless it receives the same tasks and both arms. Preserve IWC's continuous agreement endpoint separately from binary benchmark acceptance.
2. Freeze before/after/code populations and whether the quoted ratio is a ratio of aggregate totals, a ratio of medians, or the median of within-task/configuration ratios. Publish per-run token data and missingness, and retain every attempted run in the scientific-outcome denominator.
3. Use the same complete analysis prompt and resource limits apart from the randomized enhancement. Match agent runtime, token/compute budgets, caching policy and concurrent queue conditions. Replicates are repeated attempts, not matched random seeds. Randomize version/order within task and configuration, with isolated histories and no cross-run answer reuse.
4. Primary resource endpoint: paired task/configuration change in recorded cumulative input tokens including cache. Secondary endpoints: uncached input, output, API actions and returned text, latency, compute and provider cost when available. Separate top-level usage from campaign/subagent usage rather than quietly omitting it. Characters are a context proxy, not call-level token attribution.
5. Prespecify scientific acceptance, independent replay and parameter fidelity as quality guards. Authors must justify practical margins before seeing enhancement outcomes. Lower API use alone can represent a skipped validation step; fewer tokens are desirable only when the retained evidence and scientific quality satisfy the guards.
6. Use source-capsule clustering for BixBench and task clustering for CompBio and IWC. Report both pooled and model-specific estimates with uncertainty. For the collaborator's GPT-5.5 50-task × three-replicate example, the nominal number of attempts is 150 per arm/version, but the independent task/capsule population determines precision. Power must be evaluated on those units, not asserted from 150 alone.
7. Publish a versioned manifest, the complete outcome and usage ledger, exclusions, cache receipts and a worked failure case. A failure should expose an actionable phase/message and the full diagnostic without requiring all logs in every model turn.

## Handling provisional numbers

The collaborator's informal 55.2% reduction, 5.5× to 2.8× comparison and earlier 13× ratio have no raw cohort/estimator mapping in this package. They should appear only in internal planning records until audited. Under a fixed code denominator, 5.5× to 2.8× corresponds arithmetically to a 49.1% reduction; a 55.2% reduction applied to 5.5× yields about 2.46×. Different populations, cached/uncached definitions or estimators could explain the difference. This arithmetic does not establish which figure is correct and is not a reason to reconstruct missing results.

Suggested eventual panel: three paired version columns (baseline, round 1, round 2) beside the fixed code comparator; show within-task ratios and uncertainty, complete-cell counts, scientific acceptance/replay/fidelity guards and a compact version table. Until finalized, the panel should contain the intervention boxes X/Y/Z and the measured endpoints, without simulated bars, percentages or significance marks.

## Illustrative examples — not historical change claims

- **Compact tool card:** return the tool identifier/version, operation, input/output datatypes, required settings and a full-schema file/hash; retrieve a conditional branch only when needed. This may reduce repeated large schema context while preserving the exact parameters used.
- **Incremental history receipt:** return only newly created dataset IDs/states and a link to the complete immutable history snapshot. Preserve failed datasets and provenance; do not suppress them to shorten a summary.
- **Resumable execution receipt:** submission yields a job receipt, a wait yields state plus requested/effective parameter comparison and final outputs. Timeouts return the same resumable job identity and actionable diagnostic.
- **UDT preflight:** lint/render a representation and verify dependencies/dispatch before the scientific job. Record the preflight as a distinct operation and count its cost. The archive's probe UDTs motivate this feature but do not establish its savings.
