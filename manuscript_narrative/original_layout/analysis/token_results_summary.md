# Evidence for the token and interface section (Results 4)

Generated by `scripts/token_analysis.py` (`token_results.json` and `token_*.csv`) from retained summaries, grades and call tables. No agent or Galaxy job was run and no private grader key was opened. All comparisons concern the four primary Codex configurations; Astra and the superseded harness are excluded.

## Arm comparison: ratio of totals is primary

The primary measure is total Galaxy input divided by total code input over eligible paired task–configuration cells (three recorded usages per arm), because it reflects aggregate consumption and matches the definition used in the developers' reported ratios. The median of within-cell ratios weights every task equally and is reported as a secondary measure. The two differ because a minority of code runs consume very large inputs.

| IWC, nine tasks | 0.90 (0.46–2.88) | 1.42 (1.06–2.23) | 1.75 (0.71–5.18) | 36 |

By configuration (input, ratio of totals): BixBench GPT-5.5 2.82, Sol 3.46, Luna 6.33, DeepSeek 3.68; CompBioBench 2.12, 3.77, 3.02, 2.18; IWC 0.41, 1.72, 0.97, 0.88. Nine of 12 point estimates exceed one; all 12 uncached point estimates do. On IWC, code runs on ATAC-seq averaged 30.3 million input tokens against 7.9 million in Galaxy, and on the mitogenome task 13.4 against 5.7 million (`token_iwc_task_inputs.csv`). The claim "Galaxy uses more tokens on all benchmarks and models" therefore holds for BixBench and CompBioBench but not for IWC total input.

The GPT-5.5 BixBench ratio of totals, 2.82 (2.12–3.81), reproduces the developers' reported "2.8×" for the post-change interface. The archived runs thus represent the interface after the reported development rounds; they are the baseline for further reductions, not the earlier 5.5× or 13× states.

Within discordant sets, median rejected/accepted sibling input ratios were 0.86 (0.66–1.36) and 1.02 (0.64–1.63) for BixBench code and Galaxy, and 1.05 (0.81–1.65) and 0.90 (0.68–1.40) for CompBioBench (19, 15, 66 and 52 sets). No consistent difference; this does not establish independence.

## Model trade-offs

On tasks with complete records in all eight model–arm groups (50, 86 and nine tasks), GPT-5.5 is on the point-estimate frontier in six of six benchmark–arm views and Sol in five; with mean instead of median single-run input, five and four. Luna is dominated in all six views and DeepSeek V4 Pro in five. Sol gives the highest CompBioBench agreement and IWC code agreement at higher input than GPT-5.5. "Sol is the best model relative to its token usage" should read "GPT-5.5 and Sol form the accuracy–token frontier; Luna and DeepSeek are dominated".

## Interface costs

- **Volume and tokens.** 66,316 Galaxy calls in the primary configurations. Per-run Galaxy input correlates with interface calls plus shell commands (Spearman ρ = 0.89, 0.86, 0.83).
- **Discovery.** Search plus inspection are 46.7%, 43.5% and 53.5% of calls and 69.1%, 43.5% and 50.8% of returned text. Of tools inspected within a run, 45.1%, 47.3% and 53.0% were never run in that run. 417 calls failed because the tool identifier did not exist. Search transport almost never failed; retrieval relevance remains unlabelled.
- **Failure classes.** 7,354 failed primary calls (reconciles with the failure union): 3,155 rejected before a job ran (history-context schema 1,119; parameter value 769; tool ID 417; foreign ID 253; nested keys 215), 3,341 failed during execution (no diagnostic 1,601; runtime stderr 1,437), 858 other.
- **UDTs.** 50.6% of 4,960 calls returned ok. On CompBioBench, 32.1% of UDT calls ended in a job error without diagnostic text. Of 2,008 failed UDT jobs, 1,298 (64.6%) failed before execution without diagnostic text. After a failed job without diagnostic text, 784 of 1,567 next calls (50.0%) were identical resubmissions, and 615 of these (78.4%) failed again. 43.5% of CompBioBench Galaxy runs contain probe/preflight-named UDTs.

These measurements map to interventions: relevance-ranked search and reusable inventories (discovery); history-scoped schemas returning only relevant parameters (A1, A4); UDT dependency and dispatch preflight with actionable diagnostics (B2, identical resubmissions, probes); compact responses with retrievable full records (returned text). Combined run-and-wait endpoints and parameter checks already exist in the archived interface.
