# Galaxy improvement report

Retrospective audit, 24 September 2026. Scope: all supplied BixBench, CompBio, and IWC archives.

**The main finding is that operational success, scientific correctness, and benchmark acceptance are different outcomes in these archives.** Galaxy has substantial, concrete interface friction, but several of the clearest scientific failures happen after useful results are already available. Conversely, some rejected answers are equivalent to the reference, and some accepted answers depend on undocumented reference choices. Improving only tool execution would leave both problems unresolved.

The strongest demonstrated agent failures are choosing an incorrect mitochondrial contig from length/depth alone; submitting a candidate after recognizing inadequate support; treating self-alignment as independent validation; implementing BH adjustment incorrectly; using scientific-notation values with the wrong sort mode; and trusting contradictory tool metrics. The strongest benchmark defects are inconsistent answer normalization, unspecified analysis populations/software versions, and missing or conflicting item-level scores.

## Scope, evidence, and limits

There is no `./BixBench` directory in this checkout. This audit uses `./BixBench_50`, alongside `./CompBio` and `./IWC`. No specific task identifier was supplied, so the report covers all three collections. Existing run outputs were treated as fixed retrospective submissions. No archived agent program was executed, no Galaxy job was submitted, and hidden `ground_truth/` material was not opened.

All **203,941 files, totaling 6,818,834,519 bytes**, were read for a path/size/SHA-256 inventory. All 160 canonical task-evidence documents and 4,240 run records were parsed. The 4,228 available primary traces were decompressed/read: 3,189,362 lines, of which 1,843 were not parseable as individual JSON objects. These lines remain accessible in the original traces; normalized evidence provides another view. Twelve CompBio records have no primary trace. “All files read” does not mean that every binary artifact received independent scientific interpretation.

Every recorded BixBench rejection and IWC zero has an individual entry in the failure ledger below and a linked evidence dossier. Dossiers preserve call/result excerpts, original evaluator links, and primary/secondary attribution with confidence. Where the trace does not isolate a causal mistake, the entry says **unresolved**. A score difference, a minority answer, a nonzero process exit, or a later successful job is not sufficient evidence of a reasoning failure or recovery.

Independent checks in this audit cover all 24 IWC mitochondrial FASTAs, all 48 saved IWC bulk/pseudobulk differential-expression tables, all 24 ASV-table headers, the cryptic-exon coordinate/junction evidence, and specified arithmetic/semantic checks. They do **not** constitute a fresh gold-standard reanalysis of all 160 tasks. In particular, public gene facts cannot establish a dataset-specific maximum correlation, enrichment odds ratio, or DE count.

## Independently checked scientific failures

### Cryptic exon: useful Galaxy evidence was present, but the wrong inference was made

CompBio `cryptic-exon-q1` asks for a highly expressed protein-coding gene with a cryptic exon formed by two novel splice junctions. Of 25 submissions, 23 name **GNG10**. DeepSeek Galaxy r2 names **CD74** and r3 names **UBC**. Agreement among the other runs is corroboration only; the decisive checks are genomic location and the junction construction.

NCBI places GNG10 on GRCh38.p14 chromosome 9, **111,661,605–111,670,226**, on the forward strand. In the failing r2 run's own retained STAR output, introns **111,661,716–111,664,536** and **111,664,590–111,666,814** have **43 and 36 uniquely mapping reads**, respectively, and zero multimappers. They bracket a **53-bp exon at chr9:111,664,537–111,664,589**. The successful GPT-5.5 Galaxy r1 output explicitly constructs this pair inside a known intron. This connects the candidate to the requested event, rather than merely identifying a familiar gene. [NCBI GNG10](https://www.ncbi.nlm.nih.gov/gene/2790); [rechecked retained rows](</Users/4475918/Projects/Galaxy_benchmark/analysis_reports/galaxy_improvement_20260924/independent_checks.json>).

**DeepSeek Galaxy r2: primary reasoning/domain criterion error; secondary interface overhead.** The trace first filters STAR support (`c7>10`, L221), then annotation novelty (`c6==0`, L255), groups overlaps and retains genes with at least two records (`c2>=2`, L283), and finally searches `c1.find("CD74")>=0` (L285). Two records assigned to the same gene are insufficient: they must be compatible junctions bracketing a previously intronic segment. The stronger GNG10 pair was already in the run's data. CD74's canonical locus is on chromosome 5, not this chromosome-9 event. This is not a case where the platform prevented the correct evidence from being produced. [r2 trace](</Users/4475918/Projects/Galaxy_benchmark/CompBio/analysis/cryptic-exon-q1/source_snapshots/huggingface_traces/files/galaxy_codex_deepseek_v4_pro_0813_r2/agent_workspace/run_trace/codex_events.jsonl.gz>) (L221; decompressed line numbering); [NCBI CD74](https://www.ncbi.nlm.nih.gov/gene/972).

**DeepSeek Galaxy r3: primary acceptance of biologically inadequate evidence; secondary annotation/discovery complexity.** The RefSeq STAR rows at L266 include:

```text
chr12 124912183 124912236 2 2 0 0 1 27
chr12 124912183 124912464 2 2 0 0 1 27
chr12 124912411 124912464 2 2 0 0 1 27
```

Here STAR column 7 is unique support: **zero**. Column 8 is multimapping support: **one**. These cannot meet a strong unique-support criterion. They also lie inside the existing long UBC exon shown by the run's RefSeq transcript inspection, rather than establishing a new intronic exon. Changing annotation makes a junction's “annotated” flag change; that does not make the underlying biological event novel. UBC is a polyubiquitin precursor at chr12:124,911,646–124,914,650 on the reverse strand, making repetitive-sequence ambiguity a plausible alternative explanation, not a proven new exon. Expression count 200/rank 65 and a correct gene-coordinate lookup do not repair the missing event evidence. [r3 trace](</Users/4475918/Projects/Galaxy_benchmark/CompBio/analysis/cryptic-exon-q1/source_snapshots/huggingface_traces/files/galaxy_codex_deepseek_v4_pro_0813_r3/agent_workspace/run_trace/codex_events.jsonl.gz>) (L266; decompressed line numbering); [NCBI UBC](https://www.ncbi.nlm.nih.gov/gene/7316).

**What the stronger run did differently.** GPT-5.5 Galaxy r1 represented the actual predicate: two supported junctions splitting a known intron, with protein-coding annotation and an explicit intervening exon. It recovered from a sort-wrapper limitation by using a Galaxy custom tool, while preserving the biological test. Merely obtaining two gene overlaps or checking a candidate's name was not its stopping rule. [successful trace](</Users/4475918/Projects/Galaxy_benchmark/CompBio/analysis/cryptic-exon-q1/source_snapshots/huggingface_traces/files/galaxy_codex_gpt_5_5_r1/agent_workspace/run_trace/codex_events.jsonl.gz>) (L55; decompressed line numbering). ### Pseudobulk: a concrete statistical bug survived superficial validation

IWC custom DeepSeek r3, `wf_010_pseudobulk_scrna_de`, obtains a DE result and then overwrites adjusted p-values with this code at L60:

```python
order = np.argsort(pval)
fdr_sorted = np.minimum(1, pval[order] * len(pval) / np.arange(1, len(pval) + 1))
fdr_sorted = np.maximum.accumulate(fdr_sorted)
```

For sorted p-values, BH adjusted values require the **reverse cumulative minimum** of `n*p[j]/j`, capped at 1, followed by restoration of original order. Forward cumulative maximum is a different transformation. The run's L63 checks finiteness, range, counts, and identifiers; all can pass with the wrong transformation. L73 nevertheless describes the result as BH-adjusted. [trace and implementation](</Users/4475918/Projects/Galaxy_benchmark/IWC/analysis/wf_010_pseudobulk_scrna_de/source_snapshots/huggingface_traces/files/open_ended_code_codex_deepseek_v4_pro_r3/agent_workspace/run_trace/codex_events.jsonl:60>) (L60; decompressed line numbering); [SciPy's documented BH implementation](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.false_discovery_control.html).

My independent recomputation finds **1,065 of 1,429 rows differ by more than 10⁻⁶**, with maximum absolute error **0.00341735765**. For GPBP1, p=0.8465210404, reported FDR=0.9351776827, and recalculated BH=0.9317603250. The other 47 bulk/pseudobulk result tables pass this particular BH check. That does not certify their count models or biological contrasts.

**Primary cause:** statistical algorithm error. **Secondary:** the run repaired NumPy/Dask dependency and count-matrix orientation errors earlier; those were real overhead but not the final defect. Stronger runs retained or correctly reproduced library adjusted p-values. A semantic invariant—recompute BH on the saved p-vector—isolates the failure much more sharply than “the job finished.”

## Changes that would improve Galaxy and agent results

The following are recommendations derived from the observed failures, not claims that no Galaxy component currently provides related functionality. The responsible layer matters: server/wrapper, agent-facing adapter, analysis workflow, and benchmark evaluator need different changes.

The clearest successful behavior was **checking the scientific predicate**, not merely completing more tools. Strong cryptic-exon runs built the exon from its junctions; strong mitochondrial runs checked identity and completeness; correct BH runs used a valid transformation; successful API recoveries preserved the original objective and inspected the effective parameters. Some accepted BixBench runs instead matched an older implementation or a particular input subset. Those should inform reproducibility contracts, not be taught as universally superior biological reasoning.

Before claiming improvement, replay a frozen set of these cases across both tracks with the same model, prompt, budgets, references, and evaluator version. Measure scientific validity, allowed-input compliance, operational completion, unsuccessful retries, and stage-attributed token/elapsed-time use separately. Include valid alternative routes and negative candidates so that the new checks reward evidence rather than conformity to one workflow. This retrospective archive alone cannot estimate a causal accuracy gain for any proposed change.
