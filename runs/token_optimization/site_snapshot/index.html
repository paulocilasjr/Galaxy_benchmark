What changed in the third optimization round

  • Shorter successful replies

    Return job status, dataset identifiers, relevant results and check summaries. Bound inline text previews; keep full requests, replies and job details for later inspection. Error details remain available.

  • Avoid repeated content

    Deduplicate output datasets and abbreviate unchanged results and tool schemas within a session. A tool schema is still checked against the live Galaxy interface and can be expanded again.

  • Clearer submission formats

    Remove repeated parameter descriptions and provide generic templates with actual parameter paths. These describe how to call the selected tool, not how to solve a benchmark question.

  • Fewer format-related retries

    Correct false parameter-mismatch alarms caused by equivalent repeat-field names or different API input formats. Check custom-tool input/output definitions before creation; keep scientific parameter checks.

  • Longer waits between model requests

    Use the approved waiting instructions: wait at least five minutes, preferably thirty, rather than repeatedly asking whether an asynchronous call has finished. The Galaxy tool interface already waits for jobs; this change reduces the model's checks of that still-running call.

Full execution evidence is retained despite the shorter conversation.

Run configuration

Workers used only the benchmark's Galaxy tools; additional account-connected tools were disabled.

These are observed batch comparisons; savings were not measured separately for each individual change. Run selection is recorded in the batch manifest, and original attempts remain retained locally.
